# P0 启动链毕业检查表

> 这个页面不新增知识，只用于决定“是否可以进入 001 GPIO”。

## A. CPU 与地址

- [ ] 我能解释 CPU 直接执行的是机器指令，不是 C 源码。
- [ ] 我能解释 PC 如何影响接下来从哪里取指。
- [ ] 我能区分“地址”和“地址里的值”。
- [ ] 我能解释函数为什么有地址。
- [ ] 我知道函数入口值与 Cortex-M Thumb bit 的关系。

## B. Flash / RAM

- [ ] 我能解释程序为什么长期存放在 Flash。
- [ ] 我能解释运行时变量为什么大量使用 RAM。
- [ ] 我知道 RAM reset 后的旧内容不能被随意假设。
- [ ] 我能解释 `.data` 为什么同时关联 Flash 与 RAM。
- [ ] 我能解释 `.bss` 为什么占 RAM 但不需要同尺寸 Flash 初值。

## C. Linker

- [ ] 我能解释 `MEMORY` 与 `SECTIONS` 的职责差别。
- [ ] 我能解释 input section 与 output section 的基本关系。
- [ ] 我知道 linker symbol 不是自动分配出来的普通 C 变量。
- [ ] 我能解释 `_estack/_sidata/_sdata/_edata/_sbss/_ebss`。
- [ ] 我能解释 VMA/LMA。
- [ ] 我知道 `ALIGN` 可能产生 padding。
- [ ] 我知道为什么 `.isr_vector` 常使用 `KEEP()`。

## D. Cortex-M Reset / Startup

- [ ] 我能解释 CPU 为什么不直接找 `main()`。
- [ ] 我知道 vector[0] 是 initial MSP。
- [ ] 我知道 vector[1] 是 Reset Handler 入口。
- [ ] 我能说清向量表由谁定义、谁链接、谁烧录、谁使用。
- [ ] 我能解释 Startup 文件本身也是程序的一部分。
- [ ] 我能识别 Reset_Handler 中 `.data` copy 与 `.bss` clear。
- [ ] 我能解释 weak handler 的工程意义。

## E. ELF

- [ ] 我知道 ELF 不等于原始 `.bin`。
- [ ] 我能区分 Section 与 Segment。
- [ ] 我知道 ELF Header / Section Header / Program Header 各看什么。
- [ ] 我会用 `size` 看规模。
- [ ] 我会用 `nm` 看 symbol。
- [ ] 我会用 `objdump -h/-d` 看 section 与反汇编。
- [ ] 我会用 `readelf -h/-S/-l/-s` 交叉检查。

## F. Debugger 实证

- [ ] 我实际读取过向量表前两个 word。
- [ ] 我解释过 vector[1] 与 Reset_Handler symbol 的 Thumb bit 差异。
- [ ] 我在 Reset_Handler 附近停下看过 MSP/PC。
- [ ] 我单步或断点观察过 `.data` copy 前后变化。
- [ ] 我单步或断点观察过 `.bss` clear 前后变化。
- [ ] 我确认过 `SystemInit/runtime/main` 的真实控制流顺序。
- [ ] 我能区分“ELF 静态证明”和“运行时证明”。

## 通过标准

不是要求每一个架构细节都背下来。

而是：

> 以上关键项基本能独立解释，并完成一次真实启动追踪。

达到这里即可正式进入 GPIO；以后遇到中断、DMA、Bootloader、RTOS 时再回到对应节点继续加深。
