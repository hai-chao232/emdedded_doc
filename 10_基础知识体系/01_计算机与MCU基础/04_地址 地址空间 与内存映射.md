# 地址、地址空间与内存映射

## 一句话先说清

地址是 CPU 用来定位“某个可访问位置”的编号。地址空间是所有可表示地址的集合；内存映射则规定不同地址区间分别由 Flash、SRAM、外设或 Cortex-M 系统组件响应。

---

## 1. 地址和数据是两件不同的东西

假设：

```text
地址：0x20000000
内容：0x12345678
```

可以画成：

```text
0x20000000 ──→ [ 0x12345678 ]
   地址             值
```

不要把：

```text
0x20000000
```

误认为“这里存的值”。

它首先是一个位置编号。

---

## 2. 为什么 CPU 需要地址？

因为 CPU 要表达：

```text
从哪里读？
往哪里写？
从哪里取下一条指令？
```

例如：

```text
PC = 0x08000278
```

表示 CPU 在代码地址附近执行。

而：

```text
R0 = 0x20000000
```

可能表示 R0 暂时保存一个 SRAM 地址。

---

## 3. 32 位地址意味着什么？

Cortex-M4 使用 32-bit address space：

```text
0x00000000
...
0xFFFFFFFF
```

理论编号范围：

```text
2^32 Bytes = 4 GiB address space
```

这不代表 STM32F446 真的有 4 GiB 物理 RAM。

只是：

> CPU 可以发出这么多不同的地址编号。

不同区间由不同硬件响应。

---

## 4. “地址空间”不是“RAM 大小”

这是非常重要的一点。

```text
32-bit address space
```

不等于：

```text
4 GB physical RAM
```

就像一栋楼有 10000 个房间号规则，但实际可能只建了其中一部分。

未实现区域访问可能：

- 返回特定结果
- 触发 BusFault
- 被保留
- 映射到别的设备

---

## 5. Cortex-M 的粗粒度地址地图

先建立最粗的地图：

```text
0x00000000
┌────────────────────────────┐
│ Code / boot related region │
├────────────────────────────┤
│ SRAM region                │
├────────────────────────────┤
│ Peripheral region          │
├────────────────────────────┤
│ External memory/device ... │
├────────────────────────────┤
│ System / PPB               │
└────────────────────────────┘
0xFFFFFFFF
```

对于当前 STM32F446，最常接触：

```text
Flash      0x08000000...
SRAM       0x20000000...
Peripherals 0x40000000...
Cortex-M system 0xE000....
```

---

## 6. STM32F446 当前 P0 重点区域

```text
Main Flash
0x08000000
    │
    │ 512 KiB
    ▼
0x08080000  end boundary


SRAM
0x20000000
    │
    │ 128 KiB
    ▼
0x20020000  end boundary
```

这两个区间为什么重要？

因为 linker script 就是在告诉 linker：

> 当前固件主要可以怎样使用这些地址。

---

## 7. 外设也被分配地址

例如 GPIO、RCC、USART 都有地址。

因此：

```text
0x400xxxxx
```

附近并不一定是普通 SRAM。

当 CPU 对某个外设寄存器地址执行 load/store 时，芯片内部总线把这个访问送给对应 peripheral。

所以：

```c
RCC->AHB1ENR
```

最终仍然是“访问一个地址”。

## 8. 地址映射是谁决定的？

不同层次分别决定不同事情：

### ARM Cortex-M 架构

规定大区域的体系结构映射和系统地址区域。

### ST 的 STM32F446 芯片设计

在这些框架下决定：

```text
Flash 实际在哪里
SRAM 实际多大
GPIOB 基地址是多少
RCC 基地址是多少
```

### Linker Script

不是创造物理内存，而是告诉 linker：

> “这次程序允许使用其中哪些区域，怎么放 section。”

---

## 9. Boot alias 为什么会出现？

STM32 上一个容易困惑的现象：

```text
Main Flash 实际地址：0x08000000
```

但 Cortex-M reset 取初始向量时从：

```text
0x00000000
```

开始。

STM32 的 boot memory mapping 可以让启动时：

```text
0x00000000
```

映射 / alias 到所选择的 boot memory，例如主 Flash。

所以正常 Flash boot 时，可以概念理解为：

```text
0x00000000 ──alias──> 0x08000000
```

这也是为什么你后面学向量表时必须区分：

```text
向量表链接位置
启动时 CPU 的取址位置
VTOR 后续指向
```
