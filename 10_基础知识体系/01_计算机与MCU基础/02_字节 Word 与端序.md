# 字节、Word 与端序

## 一句话先说清

内存通常按“字节地址”编号；一个 32 位整数占 4 个连续字节。端序决定一个多字节数的高低字节分别放到较低还是较高地址。

---

## 1. Byte 是内存寻址的基本单位

在 Cortex-M 常见语境中：

```text
地址 +1
```

表示前进 1 Byte，而不是 1 个 32 bit word。

例如：

```text
0x20000000
0x20000001
0x20000002
0x20000003
```

是 4 个连续字节地址。

---

## 2. `uint32_t` 占多少？

```c
uint32_t x;
```

通常：

```text
32 bit = 4 Bytes
```

如果 `x` 从：

```text
0x20000000
```

开始，占：

```text
0x20000000
0x20000001
0x20000002
0x20000003
```

下一个自然对齐的 `uint32_t` 可从：

```text
0x20000004
```

开始。

---

## 3. Word 是什么？

“word”是上下文相关词。

在 ARM Cortex-M4 的常见文档里：

```text
byte      = 8 bit
halfword  = 16 bit
word      = 32 bit
```

但不要把“word 永远等于 32 bit”推广到所有 CPU 架构。

---

## 4. 小端序 Little Endian

假设：

```c
uint32_t x = 0x12345678;
```

小端序把最低有效字节放在最低地址：

```text
地址          内容

0x20000000    0x78
0x20000001    0x56
0x20000002    0x34
0x20000003    0x12
```

所以内存 dump 可能看起来是：

```text
78 56 34 12
```

但读取一个 32 bit word 仍得到：

```text
0x12345678
```

---

## 5. 为什么你后面看到 `10` 会是 `0A 00 00 00`？

如果：

```c
uint32_t counter = 10;
```

十六进制：

```text
10 decimal = 0x0000000A
```

小端存储：

```text
0A 00 00 00
```

所以在 `objdump -s` 或 debugger memory bytes 中看到这一串，不要误以为数值变了。

---

## 6. 端序影响“多字节解释”，不改变单个字节

一个 byte：

```text
0xAB
```

不存在内部字节顺序问题。

端序只在：

```text
16 bit
32 bit
64 bit
...
```

这种多字节对象上体现。

---

## 7. 对齐 Alignment 是什么？

32 bit 数据常希望地址为 4 的倍数：

```text
0x20000000 ✅
0x20000004 ✅
0x20000008 ✅
```

而：

```text
0x20000001
```

不是 4-byte aligned。

Cortex-M4 支持部分非对齐访问，但某些指令、外设和配置存在限制；工程中通常仍尽量保持自然对齐。

---

## 8. Linker 为什么会插 padding？

如果前一个 section 结束在：

```text
0x08000102
```

而下一个对象要求 4-byte 对齐，linker 可能把位置推进到：

```text
0x08000104
```

中间的两字节就是对齐填充。

因此：

> “源码对象大小相加”不一定精确等于最终 section 大小。

---

## 9. 地址图

```text
低地址
  ↓

0x20000000  [ byte0 ]
0x20000001  [ byte1 ]
0x20000002  [ byte2 ]
0x20000003  [ byte3 ]
0x20000004  [ next ... ]

  ↑
高地址
```

一个 32 bit word 横跨 4 个相邻 byte 地址。

---

## 10. 常见误区

### “地址 0x20000004 是第 4 个 word”

不准确。

它是比 `0x20000000` 高 4 Bytes 的地址。

### “小端所以 CPU 从右往左执行”

完全无关。端序说的是多字节数据的 byte 排列，不是代码执行方向。
