# 指针到底是什么？

## 一句话先说清

指针本质上是一个“保存地址的值”。类型告诉编译器：当你通过这个地址访问时，应该把多少字节按什么类型解释。

---

## 1. 普通变量保存数据

```c
uint32_t x = 10;
```

假设 linker 把 x 放到：

```text
0x20000020
```

则：

```text
x 的地址 = 0x20000020
x 的值   = 10
```

这是两件事。

---

## 2. 指针变量保存地址

```c
uint32_t *p = &x;
```

现在：

```text
p 的值 = 0x20000020
```

而：

```c
*p
```

表示：

> 到 `p` 保存的地址那里，以 `uint32_t` 方式访问。

---

## 3. 图

```text
p
┌──────────────┐
│ 0x20000020   │
└──────┬───────┘
       │
       │ points to
       ▼
0x20000020
┌──────────────┐
│ 10           │  x
└──────────────┘
```

## 4. 为什么指针和 MCU 寄存器密切相关？

外设寄存器有固定地址。

如果：

```text
RCC base = 某个固定地址
```

Device Header 可以构造一个指针：

```c
RCC_TypeDef *RCC
```

指向那里。

于是：

```c
RCC->AHB1ENR
```

本质：

```c
(*RCC).AHB1ENR
```

也就是通过地址访问对应偏移。

---

## 5. 指针类型有什么用？

假设：

```c
uint8_t *p8;
uint32_t *p32;
```

都可能保存：

```text
0x20000000
```

但：

```c
*p8
```

通常读取 1 Byte。

```c
*p32
```

通常读取 4 Bytes。

而：

```c
p8 + 1
```

地址加 1 Byte。

```c
p32 + 1
```

地址加 4 Bytes。

---

## 6. `&` 和 `*`

### 取地址

```c
&x
```

得到 x 的地址。

### 解引用

```c
*p
```

访问 p 指向的对象。

不要把：

```text
* 出现在声明里
```

和：

```text
* 出现在表达式里
```

机械当成完全同一语法角色，但核心都与“指向某类型”有关。

---

## 7. 指针和整数地址可以转换，但要谨慎

底层代码常见：

```c
(volatile uint32_t *)0x40000000
```

表示：

> 把这个整数地址解释成一个指向 volatile uint32_t 的指针。

然后：

```c
*(volatile uint32_t *)0x40000000
```

表示：

> 访问这个地址处的 32-bit volatile 对象。

这正是 MMIO 最底层的 C 模型之一。

---

## 8. 指针不等于“真的存在一个对象”

你可以构造：

```c
uint32_t *p = (uint32_t *)0xDEADBEEF;
```

C 语法允许形成这个值。

但如果 CPU 真去解引用一个没有有效硬件响应的地址，可能：

```text
BusFault
HardFault
```

所以：

> 指针值合法的 C 表达式，不等于它指向有效 MCU 内存。

---

## 9. 指针与 Linker Symbol

在 C 代码中有时会看到：

```c
extern uint32_t _sdata;
```

然后使用：

```c
&_sdata
```

这里很容易误解。

Linker symbol 不是普通 C 变量，但通过这种声明技巧，可以让编译器生成对该 symbol 地址的引用。

真正关心的往往是：

```text
&_sdata 的数值
```

而不是 `_sdata` 地址处存了一个普通变量。

---

## 10. 常见误区

### 指针就是地址

更精确：

> 指针是带有类型语义的地址值。

### `p` 和 `*p` 是一个东西

不是。

```text
p  = 地址
*p = 该地址对应对象的值/访问
```

### 地址越大，数据越大

完全无关。
