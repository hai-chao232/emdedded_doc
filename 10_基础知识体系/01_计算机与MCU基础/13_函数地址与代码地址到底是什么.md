# 函数地址与代码地址到底是什么

## 1. 为什么函数能有地址

源代码里：

```c
void foo(void)
{
    /* ... */
}
```

编译、汇编、链接后，`foo` 会变成一串机器指令，并被安排到可执行存储区域。

例如：

```text
0x08001000  foo 的第一批指令字节
0x08001002  ...
0x08001004  ...
```

因此链接器可以定义：

```text
foo → 代码入口相关的 symbol value
```

## 2. 函数名不是 CPU 运行时查字典

CPU 不会执行：

```text
“找到名叫 foo 的函数”
```

真正发生的是：

```text
编译/链接阶段：
foo → 解析为入口地址/重定位

运行阶段：
控制流跳到那个入口
```

## 3. `nm` 看到什么

例如：

```text
08000250 T main
08000278 T Reset_Handler
```

可先理解为：

```text
main          的代码 symbol value 在 0x08000250 附近
Reset_Handler 的代码 symbol value 在 0x08000278 附近
```

`T` 表示该符号位于 text/code 类型区域。

## 4. 函数指针为什么能工作

```c
void (*p)(void) = foo;
p();
```

`p` 中保存的不是整段函数代码，而是一个可以用来进入 `foo` 的函数入口值。

因此向量表保存 Handler 入口值，本质上与“函数指针表”有相似直觉。

但 Cortex-M 异常入口还包含架构规定，尤其 Thumb 状态位：

[[10_基础知识体系/03_Cortex-M与启动中断/15_Thumb状态与函数地址最低位]]

## 5. “函数地址”等于“第一条指令真实字节地址”吗

在 Cortex-M/Thumb 语境中，不要过早把二者写成绝对等号。

因为：

```text
ELF symbol value
函数指针表示
异常向量入口值
实际取指地址
```

之间可能涉及最低位的 Thumb 状态语义。

所以看到：

```text
Reset_Handler symbol = 0x08000278
vector entry         = 0x08000279
```

应先按 Cortex-M 函数指针/异常入口规则解释，而不是认为代码真的从奇数字节边界取一条半字指令。

## 6. 与启动链连接

```text
Startup 定义 Reset_Handler
↓
编译/链接后成为 .text 中机器代码
↓
Linker 产生 Reset_Handler symbol value
↓
向量表保存可用于异常入口的值
↓
Reset 时 Cortex-M 读取并进入该代码
```
