# 函数调用、栈帧、LR 与返回

## 一句话先说清

函数调用不是“CPU 神奇地进入另一个 C 函数”。底层是控制流跳转、参数传递、必要的现场保存，以及执行完以后恢复到调用者。

---

# 1. 一个普通调用

```c
int y = add(2, 3);
```

概念：

```text
caller
  │
  │ 准备参数
  ▼
branch with link
  │
  ▼
add()
  │
  │ 计算
  ▼
return
  │
  ▼
caller 下一条
```

---

# 2. ARM 常见参数传递

AAPCS 中常见：

```text
R0-R3
```

用于前几个参数和返回值相关传递。

例如：

```c
int add(int a, int b);
```

可能：

```text
R0 = a
R1 = b
返回 R0 = result
```

这是 ABI 的一部分。

---

# 3. LR 为什么叫 Link Register？

调用指令需要保留：

> 返回地址。

ARM 常通过 LR：

```text
R14
```

携带返回信息。

函数结尾可以通过相应指令恢复 PC。

---

# 4. 栈帧是什么？

函数执行期间，为自己在 stack 上使用的一块临时区域，可以概念称 stack frame。

可能保存：

```text
callee-saved registers
local variables
spilled temporaries
saved LR
```

不同函数、优化等级下布局可能完全不同。

---

# 5. 为什么有的函数看不到栈帧？

例如：

```c
int add(int a, int b)
{
    return a + b;
}
```

可能直接：

```text
R0 = R0 + R1
return
```

根本不需要额外 stack memory。

所以不要把“函数 = 一定 push 一堆东西”当规则。

---

# 6. Reset_Handler 调 main 也是函数调用吗？

从汇编控制流上，会看到类似：

```asm
bl SystemInit
...
bl __libc_init_array
bl main
```

`bl`：

```text
Branch with Link
```

会建立返回相关信息。

但裸机 `main()` 通常不应该返回到普通 OS。

---

# 7. 异常返回和普通函数返回不同

进入 Cortex-M exception 后，LR 可能保存特殊：

```text
EXC_RETURN
```

它告诉 CPU 异常返回时：

- 用 MSP 还是 PSP；
- 回 Thread 还是 Handler；
- 是否有扩展栈帧等。

所以：

> 中断 handler 看起来像 C 函数，但 CPU 进入/退出它的机制比普通函数调用特殊。

# 8. 为什么理解 ABI 有用？

以后调试 HardFault 时，你可能需要看：

```text
stacked PC
stacked LR
R0-R3
```

如果完全不知道函数调用和寄存器约定，就很难从现场倒推问题。

P0 不要求背完整 AAPCS，但至少知道：

```text
函数调用是一套约定，不是 C 语言名字本身在 CPU 里流动。
```
