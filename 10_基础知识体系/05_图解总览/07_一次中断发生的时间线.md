# 一次中断发生的时间线

以外部 GPIO/EXTI 为例，仅做机制总览。

```text
main 正在执行
     │
     ▼
物理引脚发生 edge
     │
     ▼
STM32 EXTI 检测
     │
     ▼
EXTI pending/request
     │
     ▼
NVIC 看到 IRQ pending
     │
     ├─ enabled?
     ├─ mask 允许?
     └─ priority 可接受?
     │
     ▼
CPU 接受 exception
     │
     ▼
硬件自动 stacking
R0 R1 R2 R3 R12 LR PC xPSR
     │
     ▼
根据 exception number
计算 vector entry
     │
     ▼
从 VTOR-based vector table
读取 handler entry
     │
     ▼
EXTIx_IRQHandler
     │
     ├─ 读取/处理外设
     └─ 清 pending condition
     │
     ▼
exception return
     │
     ▼
硬件 unstack
     │
     ▼
恢复原 PC/xPSR 等
     │
     ▼
main 从被打断位置继续
```

## 排错时从上往下

```text
有物理 edge 吗？
EXTI source 配对吗？
trigger 配对吗？
pending 有吗？
NVIC enable 吗？
priority/mask 吗？
vector entry 对吗？
handler 名字对吗？
pending 清了吗？
```

这比“中断不进就反复改 NVIC”有效得多。
