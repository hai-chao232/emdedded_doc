# 中断与主循环共享变量为什么危险？

## 一句话先说清

中断可以在主循环指令序列的中间打断执行。因此“主循环和 ISR 都访问同一变量”会引入并发语义；`volatile` 只能保证访问不被普通优化消失，不能自动保证复合操作原子。

---

# 1. 一个例子

```c
volatile uint32_t counter;
```

主循环：

```c
counter++;
```

ISR：

```c
counter++;
```

你可能以为：

```text
两个都 +1
→ 最终一定 +2
```

不一定。

---

# 2. `counter++` 不是一条抽象原子动作

可能：

```text
load counter
add 1
store counter
```

如果 ISR 在中间插入：

```text
main load 10
IRQ load 10
IRQ store 11
main store 11
```

最后只加了 1。

---

# 3. `volatile` 解决什么？

它要求相关读写真实发生。

它不把：

```text
read-modify-write
```

变成不可打断事务。

---

# 4. 解决方式取决于数据和场景

可能包括：

- 使用天然原子宽度的简单 flag；
- 临界区暂时屏蔽中断；
- 原子指令/独占访问；
- producer-consumer ring buffer 设计；
- RTOS synchronization primitive。

不能用一个通用答案覆盖所有场景。

---

# 5. 为什么现在先知道这个？

因为到了：

```text
EXTI
UART interrupt
timer interrupt
```

你马上会让 ISR 和 main 交换状态。

如果只知道“加 volatile”，很容易留下难查 bug。
