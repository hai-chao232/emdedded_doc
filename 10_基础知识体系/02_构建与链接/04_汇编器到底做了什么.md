# 汇编器到底做了什么？

## 一句话先说清

汇编器把 ARM/Thumb 汇编表示转换成机器码，并把代码、数据、symbol、relocation 等组织成 relocatable object file。

---

## 1. 汇编不是机器码本身

例如：

```asm
ldr r0, =_sdata
bl main
```

这是人可读的汇编语法。

CPU 最终执行的是编码后的 bit pattern。

Assembler 负责转换。

---

## 2. 为什么 startup `.s` 要经过 assembler？

Startup 本身是源文件。

它里面：

- 定义向量表；
- 定义 Reset_Handler；
- 引用 linker symbol；
- 定义 weak handler。

Assembler 把这些变成 `.o`，之后才能和 C 产生的 `.o` 一起链接。

---

## 3. Assembler 为什么仍然不知道所有地址？

因为：

```asm
bl main
```

此时 `main` 可能在另一个 `.o` 中。

Assembler 不能独立确定最终目标地址。

所以它会创建：

```text
symbol reference
+
relocation
```

交给 linker。

---

## 4. 汇编伪指令

例如：

```asm
ldr r0, =_sdata
```

可能是 assembler pseudo-instruction。

它不一定对应单一硬件指令，而是 assembler 根据目标值选择合适编码/字面量池策略。

所以读 startup 时：

> 不要把每一行汇编都机械理解成“一条固定 CPU 指令”。

---

## 5. `.section` 指令

Startup 里可能有：

```asm
.section .isr_vector,"a",%progbits
```

这是在告诉 assembler：

> 接下来的内容放进一个名叫 `.isr_vector` 的 input section。

之后 linker script 再决定这个 input section 最终放到哪里。
