## P0 必看范围

```text
必看    01 ～ 18     ← 从源码到 ELF 的完整流水线
必看    19           ← 读 readelf -l 的前提（Section vs Segment）
必看    20           ← 直接回答 "bss 占 RAM 为什么不占 Flash"
必看    21           ← 解释地址之间的空洞从哪来
选读    22           ← ELF 三个 Header 的结构参考，当字典查
必看    23           ← 逐段注解你自己仓库里的 STM32F446ZE.ld
选读    24           ← 数字对不上时的通用排查方法论
```

为什么 19/20/21/23 算必看而不是"深入"：

```text
它们直接服务于 P0 里那个真实问题——
size 报 bss = 1568，_ebss - _sbss 却只有 28。

  19  → 知道该看 program header 而不是 section 列表
  20  → 知道"占 RAM 不占 Flash"在 ELF 里长什么样
  21  → 解释那 1540 里为什么会多出对齐补齐
  23  → 打开 .ld，看到 ._user_heap_stack 就是那 1540 的来源
```

22 和 24 不是不重要，是**用的时候再查**：

```text
22  → 需要精确知道 e_entry / sh_flags 是什么时再翻
24  → 已经会查了之后，想把这套方法用到别处时再读
```

> [!warning] 23 必须先构建一次
> 那页里全是可以在 `embedded_lab` 里直接跑的命令。
> 没有构建产物的话，读完也验证不了，只剩背结论。

## 与启动链相关的深入节点

19～21 是理解 `05_Linker Script` 与 `07_ELF 体检` 时必须能跳过去的：

```text
19 Section 与 Segment
   → 链接/调试视角 vs 装载/运行视角

20 NOBITS / NOLOAD
   → RAM 占用 ≠ Flash 占用

21 Alignment / Padding
   → 地址之间的空洞从哪来

22 ELF 三个 Header
   → ELF 是有结构的容器，不是 bin 加后缀
```

23 和 24 是**从原理落到你自己工程**的桥：

```text
23 真实链接脚本逐段注解
   → 打开 embedded_lab/platform/stm32f446ze/linker/STM32F446ZE.ld
   → 逐段解释，并说明为什么 size.bss 里混进了 heap/stack

24 从症状到诊断
   → 数字对不上时的通用排查路径
   → 从"我讲清楚了"到"你能自己查"
```

> [!tip] 什么时候读 23 和 24
> 原理读完（10～22）**并且能构建一次之后**再读。
> 这两页里全是可以在 `embedded_lab` 仓库里直接执行的命令。
> 没有构建产物的话，读完也验证不了。

## 最终要形成的心智模型

```text
源码不是固件
.o 不是固件
linker script 不是代码
ELF 不是“只是烧录文件”
symbol 不是变量本身
section 不是物理内存
VMA/LMA 不是两个重复地址
```

当这些区别都能讲清楚，Linker 才真正算入门。
