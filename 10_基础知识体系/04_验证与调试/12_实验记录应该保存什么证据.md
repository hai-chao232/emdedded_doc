# 实验记录应该保存什么证据？

## 一句话先说清

实验记录不是流水账。它应该让未来的你能够回答：当时基于什么版本、什么预测、什么测量和什么输出得出了这个结论。

---

# 1. 最小元数据

```text
日期
主仓库 commit
submodule commit
toolchain version
build type
board / MCU
实验 target
```

---

# 2. 问题

先写：

> 这次到底要验证什么？

例如：

```text
验证 Reset_Handler 是否把 counter 的 .data 初始值复制到 SRAM。
```

不要只写：

```text
学习 startup。
```

---

# 3. 预测

```text
counter symbol 应在 SRAM
.data LMA 应在 Flash
进入 main 时 counter 应为 10
```

---

# 4. 静态证据

按需保存：

```text
size
nm
objdump -h
objdump -s
disassembly
map excerpt
```

只保存和问题有关的部分。

---

# 5. 动态证据

例如：

```text
breakpoint location
PC
SP
register values
memory before/after
peripheral registers
```

---

# 6. 物理证据

例如：

```text
万用表电压
逻辑分析仪截图
频率
占空比
串口日志
```

要写测量点和条件。

---

# 7. 故障注入

记录：

```text
破坏了什么
为什么预测会这样
实际怎样
恢复方式
```

---

# 8. 结论

好的结论：

> `.data` 的 initial image 位于 Flash；Reset_Handler 依据 `_sidata/_sdata/_edata` 复制后，main 中 SRAM counter 为 10。该结论由 ELF VMA/LMA、变量 symbol 地址和 debugger 前后内存变化共同支持。

差的结论：

> 学会了 `.data`。

---

# 9. 未解决问题

非常值得留下：

```text
为什么 size.bss 比 _ebss-_sbss 大？
VTOR 为什么是这个值？
```

然后链接到后续知识页。
