# 怎样验证向量表？

## 目标命题

> 最终 ELF 中确实有正确的 `.isr_vector`，其 initial MSP 与 Reset Handler entry 和当前链接结果一致；运行时 vector base 也处于预期位置。

---

# 1. 第一步：看 section

```bash
arm-none-eabi-objdump -h "$ELF"
```

确认：

```text
.isr_vector
```

存在，且 VMA 位于预期 Flash 起始区域。

---

# 2. 第二步：看 symbol

```bash
arm-none-eabi-nm -n "$ELF" \
  | grep -E '_estack|Reset_Handler'
```

记录：

```text
_estack = ?
Reset_Handler = ?
```

---

# 3. 第三步：看 vector bytes

```bash
arm-none-eabi-objdump -s -j .isr_vector "$ELF"
```

把第 1 个 32-bit word 按 little endian 解释：

```text
应对应 _estack
```

第 2 个 word：

```text
应对应 Reset_Handler entry
```

注意 Thumb entry 最低位语义。

---

# 4. 第四步：反汇编 Reset_Handler

```bash
arm-none-eabi-objdump -d "$ELF"
```

确认 vector 指向的目标确实是：

```text
Reset_Handler
```

不是某个意外地址。

---

# 5. 第五步：运行时看 VTOR

烧录后 debugger：

```text
读取 SCB->VTOR
```

确认它指向当前运行期预期 vector table base。

---

# 6. 更强验证：触发一个可控异常

例如后续 SysTick/EXTI 实验：

```text
给对应 handler 下断点
触发事件
确认 PC 进入 handler
```

这证明：

```text
NVIC/exception
+
vector lookup
+
handler entry
```

真实工作。

---

# 7. 如果不一致怎么分层？

```text
ELF vector 错
→ startup/linker/build

ELF 对，但 VTOR 错
→ SystemInit/vector relocation

VTOR 对但某 handler 错
→ symbol/weak override/vector entry

都对但中断不进
→ peripheral/NVIC/mask/priority
```
